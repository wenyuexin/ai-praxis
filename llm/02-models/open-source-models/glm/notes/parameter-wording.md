# GLM-5.x 参数口径笔记

## 这份笔记承接什么

这份笔记专门保留 `GLM-5.x` 系列里反复出现的参数口径问题，尤其是 `GLM-5.1`、`GLM-5.2` 的总参数 / 激活参数数字为什么暂时不宜写死。

它不是最终规格表，而是正文写法的保险丝。

## 当前已知

### 1. `GLM-5.1` 的主口径已比之前更清楚

当前整理材料中至少出现过这些数字：

- `744B / 40B`
- `754B / 40B`
- `75.4B / 4B`（明显可疑）

结合最新补调研，当前更稳的判断可以推进到：

- `754B / 40B` 已有多处高信号来源支撑，更像 `GLM-5.1` 的主公开口径
- `75.4B / 4B` 仍应视为明显异常或转述错误
- `744B / 40B` 更应优先理解为 `GLM-5` 基础版本口径，而不是 `GLM-5.1` 的最终数字

但即使如此，正文里仍不必把 `GLM-5.1` 的总参数写得过满；更稳的写法仍应保留“公开口径主要收敛到 `754B / 40B`”这一层，而不是提前展开所有统计含义。

### 2. `GLM-5.2` 的口径正在收敛，但仍需保守解释

当前公开页里也出现过：

- `744B`
- `753B`
- `754B`（多见于第三方量化 / 托管口径）
- 以及更适合写成 `740B+ / 40B active` 的保守口径

结合最新补调研，当前更合理的理解是：

- `753B` 已经比早先更像 `GLM-5.2` 的主公开数字之一
- `744B` 更像 `GLM-5` 基础版本口径，而不是 `GLM-5.2` 自己的最终口径
- `753B`、`754B` 之间的差异，很可能与是否计入 shared expert、MTP、embedding 或托管平台自己的统计方式有关

因此 `GLM-5.2` 仍不适合现在就把总参数写死成唯一数字；现阶段更稳的正文写法仍是：约 `740B+` 总参数、约 `40B` 激活参数的大规模 MoE 模型。

### 3. 不同数字不一定都在说同一个层级

当前可能混在一起的来源层级包括：

- 系列基础版本 `GLM-5` 的参数口径
- 后续版本的公开模型页口径
- 第三方平台的转述或字段抄写
- 托管服务页面的部署 / 量化 / serving 配置口径
- 是否计入 shared expert、MTP、embedding、lm_head 等模块的统计口径差异

`GLM-5` 原报告已明确写出：参数统计**计入 MTP 层参数，不计入词嵌入和输出层**。这是目前已有直接文本依据的统计边界，适用于理解 `744B` 这个数字，但不能自动推广到 `GLM-5.1` / `GLM-5.2` 的统计方式。

这意味着"数字不同"不一定等于谁真谁假，也可能是：

- 统计口径不同（如是否计入 embedding、lm_head、MTP）
- 版本对象不同
- 展示字段被简化或写错
- 第三方聚合页面存在单位错误
- HF 元数据、量化仓库元数据与官方营销口径在求和边界上不同

## 当前正文中的更稳写法

### 1. 对 `GLM-5.1`

当前更稳写法是：

- `GLM-5.1` 属于超大规模 MoE 模型
- 激活参数约 `40B`
- 总参数规模当前公开口径尚未完全统一

### 2. 对 `GLM-5.2`

当前更稳写法是：

- `GLM-5.2` 属于约 `740B+` 总参数、约 `40B` 激活参数的大规模 MoE 模型
- 总参数在不同公开页面间仍有 `744B` / `753B` 等差异

### 3. 对跨版本比较

在 `glm-5.x-evolution.md` 中，更适合比较：

- `200K -> 1M` 这类上下文窗口差异
- 发布形态与能力叙事差异
- 架构线索暴露程度差异

而不是现在就拿尚未统一的总参数数字做精细比较。

## 当前最容易误写的地方

### 1. 把 `GLM-5` 的参数数字直接套到后续版本

`GLM-5` 报告中的数字，不能因为后续版本回引了该报告，就自动写成 `GLM-5.1` / `GLM-5.2` 的最终规格。

### 2. 把第三方聚合页字段当成官方定值

像 `75.4B / 4B` 这类明显异常口径，更像：

- 单位丢失
- 小数点错位
- 页面字段展示错误

这类数字不应直接回流正文。

### 3. 把托管服务限制误当模型原生规格

某些第三方或托管页面出现的输入 / 输出窗口限制，也可能是服务配置，不等于模型原生上限。参数与窗口规格都要留这个边界意识。

## 待确认

2. `GLM-5.1` 与 `GLM-5.2` 的 Hugging Face 模型卡后续是否会统一参数口径
3. 是否存在更正式的 model card / system card / repo config 能直接解释 `744B` 与 `753B` 的差别

## 后续动作

1. 如果后续拿到官方 config，先更新这份笔记，再决定是否收紧对象文写法
2. 如果不同数字最终被证实属于不同版本节点，应在版本对象文中各自落位，而不是在系列演进文里混写
3. 如果确认某个数字只是第三方错误，应在这份笔记中保留一次“为何舍弃”的说明，防止以后又被捡回来

# GLM 系列总览

本篇是 GLM 系列的人类向主线文，帮助读者建立对 `GLM-5.x` 系列的整体理解。目录说明与文档分工见 [`README.md`](./README.md)。

## 为什么不只保留一篇总文

`GLM-5`、`GLM-5.1`、`GLM-5.2` 并不是可以互相替代的静态对象。

对这类持续演进对象，版本差异可能改变：

- 能力边界
- 上下文长度
- 接口能力
- 技术背景与公开报告关系
- 开源权重发布方式
- 服务形态与变体

因此，本目录不把多版本观察压成单一对象总览；更稳的结构是：

- `overview.md`：承接系列总览与版本关系
- 系列差异整理文：承接跨版本的演进主线与比较阅读入口
- 带版本标识的对象正文：承接具体版本对象研究
- 报告对象文：承接上游 technical report / report 本身作为研究对象时的整理文

## 当前可见的系列判断

基于现有公开材料，当前至少可以确认：

- `GLM-5` 报告可作为系列级技术背景
- `GLM-5.1`、`GLM-5.2` 都应优先按版本对象处理
- 系列公开资料常常由 blog、产品文档、模型页、系列仓库与前代技术报告共同构成，不等于"每个版本都有独立技术报告"
- 当研究目标直接转向 `GLM-5` 原报告本身时，应单独使用报告对象文承接，而不是继续把报告解读压在 `glm-5.md` 里

## 版本演进主线

`GLM-5.x` 的演进方向可以概括成三步：从 `GLM-5` 建立系列技术锚点，到 `GLM-5.1` 把"长程任务执行"变成版本对象身份，再到 `GLM-5.2` 推进到 `1M` 上下文与更明确的架构级增量。更详细的跨版本差异比较，见 [`glm-5.x-evolution.md`](./glm-5.x-evolution.md)。

## 需要保留的版本边界

- `GLM-5` 报告是系列级技术背景，不是 `GLM-5.1` / `GLM-5.2` 的独立技术报告
- `GLM-5` 的训练细节、参数规模、benchmark 不能自动外推到后续版本
- 后续版本的公开页参数口径仍有待更直接材料统一
- "8 小时持续工作""项目级工程接管"等表述更适合写成官方能力叙事，而不是脱离任务条件的固定上限

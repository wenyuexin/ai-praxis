# Incident: 研究正文的概念顺序与章节职责失序

- 当前状态：Active
- 是否复发：未复发
- 记录日期：2026-07-19

## 问题背景

在持续整理 `agentic/07-evaluation/agent-benchmarks/llm-as-a-verifier_2607.05391.md` 时，文档的目录落位、研究对象定位和 Evidence 收束均已符合现有规则，但正文前半程仍出现理解路径失序：核心概念在正式定义前被引用，同一机制分散在不同章节重复解释，方法、实验与扩展应用以不同认知职责并列在顶层。

这些局部章节分别可以成立，逐段阅读也不一定暴露问题；抽取全部标题并结合概念首次出现位置后，才看出全文缺少稳定的“定位整体框架，再进入机制与验证”的阅读依赖。

## 冲突点

`research-artifacts.md` 已覆盖研究单元类型、对象正文与辅助材料分层、正文自包含性，以及正文尾部与 Evidence 的职责归并，但没有直接约束正文前半程的概念引入顺序和同级章节职责。

因此，产物落位正确、Evidence 结构正确，并不自动保证单篇对象正文形成可连续恢复的理解路径。这个问题不是现有条文被违反，也不是单纯的标题措辞偏好，而是治理覆盖边界与复杂对象正文的长期可理解性之间出现了空白。

## 问题轨迹

1. `PPT` 缩写和局部排序机制先出现，完整名称、方法定位与必要性在后文才建立。
2. 同一 PPT 排序过程分别出现在评分方法与独立 PPT 章节，形成重复解释。
3. “方法核心”“三条 verification scaling 轴”“PPT”“benchmark 覆盖面”“实验链路”和“两个扩展”以不同职责并列为顶级章节。
4. 局部检查只能发现单个标题或句子的表达问题，未能识别全文依赖关系。
5. 只抽取章节标题并核对核心概念首次出现位置后，才确认方法组成、实验验证和扩展应用需要重新归并。

## 解决方案

### 概念顺序

将 PPT 的完整定义、用途、pivot 含义和排序过程集中到首次详细解释的位置；前文只保留必要预告，不在正式定义前展开局部机制。

### 章节职责

把连续评分、verification scaling 与 PPT 归入统一的方法职责，把 benchmark、主要实验和扩展应用归入统一的实验职责；贡献总览提前到方法细节之前，帮助读者先建立全文路线图。

### 验证方式

编辑完成后单独抽取标题，检查顶层章节是否承担稳定职责；再核对核心概念的首次引用、最小定义与详细展开顺序。该操作是本次有效的诊断方式，不构成所有研究文档必须执行的固定流程。

## 治理判断

本轮只记录 incident，不修改 `research-artifacts.md` 或 `intent/research-artifacts.md`，也不创建 case。

可迁移的观察信号包括：

- 核心概念在承担详细推理前缺少最小定义。
- 同一机制分散在多个章节重复解释。
- 同级章节承担不同认知职责，局部均成立但组合后主线失序。

论文对象中特有的边界包括：

- 作者贡献与详细方法之间存在论证顺序。
- 作者原始论证链与仓库读者所需的理解链不必机械一致。

以下内容只属于当前文档的局部选择，不应制度化：

- “研究定位 → 贡献 → 方法 → 实验 → 结论 → Evidence”的具体顺序。
- “方法框架”“实验设计与结果”等具体标题。
- 固定章节数量、标题词表或强制大纲模板。
- 将标题抽取规定为所有文档的默认检查步骤。

## 复发信号

出现以下方向性信号时，重新检查本 incident：

- 独立研究对象再次出现核心概念先展开、后定义，导致正文难以独立理解。
- 目录和产物落位正确，但同一机制仍被分散到多个章节重复解释。
- 同级章节持续混合方法、验证结果、应用扩展或综合判断，且需要人工重建上层职责。
- 协作者已读取研究产物规则，仍把“产物分层正确”误认为“正文内部结构已经得到保证”。

若这些信号形成稳定设计误读，优先考虑在 `intent/research-artifacts.md` 解释正文概念依赖与章节职责的边界；只有 intent 仍不足以阻止普通任务中的稳定误执行时，才考虑在 `research-artifacts.md` 增加短小、方向性的执行提示。确认形成复发模式后，再判断是否升级为 `cases/` 条目。

# 问题轨迹记录

本目录存放治理问题的**单次轨迹记录（incident record）**。

它与 [`../cases/`](../cases/) 的区别：cases/ 收录已确认的复发模式案例；本目录收录单次出现但带有完整轨迹的问题记录，便于下次出现同类问题时对照。

## 放什么

- 单次出现的治理问题，带有完整背景、冲突点和解决方案
- 问题尚未形成稳定复发模式，但轨迹足够完整，值得长期保留
- 问题已经通过规则修改解决，但保留记录作为规则变更的历史轨迹

## 不放什么

- 没有结构化背景和解决方案的零散感想
- 已确认的复发模式案例（放 [`../cases/`](../cases/)）
- 主规则本体
- 日常任务记录

## Incident 记录的最小字段

- 问题背景：什么场景下出现的
- 冲突点：当前规则与实际情况之间的矛盾在哪里
- 解决方案：如何处理的
- 是否复发：首次记录时标"未复发"；后续如复发则更新
- 当前状态：Active / Resolved / Archived
- 关联文件：涉及的规则文件和文档

## 生命周期

- **Active**：问题可能复发，保持关注
- **Resolved**：已沉淀为规则，或已确认不再复发；保留作为历史轨迹
- **Archived**：长期未复发，清理归档

升级路径：
- 如复发：升级为 [`../cases/`](../cases/) 中的已确认模式案例，或直接推动规则修改
- 已沉淀为规则的 incident：标记为 Resolved

## 什么时候才读

- 准备修改规则前，检查是否有已记录的同类问题（[`../rules/meta-rules.md`](../rules/meta-rules.md) §1）
- 遇到似曾相识的治理问题时，查找是否有类似 incident 可对照
- 需要理解某条规则的变更背景时，查看关联的 incident 记录

## 与主规则、`intent/`、`cases/` 的关系

- 主规则负责：路由、职责边界、stop-line、默认执行顺序
- `intent/` 负责：解释规则背后的设计原理与概念边界
- `cases/` 负责：已确认复发模式的边界案例与误判复盘
- 本目录负责：单次问题轨迹记录，支持复发识别和规则沉淀

因此，主规则保持短；`intent/` 解释"为什么这样定"；`cases/` 说明"复杂场景里具体怎么用"；本目录记录"这个问题出现过，下次可以对照"。

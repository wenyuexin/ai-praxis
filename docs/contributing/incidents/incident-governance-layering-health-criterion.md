# Incident: 治理层缺少“分层健康度”判据

- 当前状态：Resolved
- 是否复发：未复发
- 记录日期：2026-09-16
- 触发类别：§1 高危维度 · 高迁移成本

## 问题背景

在收敛 `meta-rules.md` §1 的改规则触发器时，顺带暴露出一个更上位的缺口：治理文档层（capabilities / rules / intent / cases / incidents）已增长到数十篇，部分任务的路由需要跨层读 4–6 篇，但 `organization-principles.md` 只从分类轴一致性、语义边界、迁移成本等角度评价**知识内容目录**，没有任何判据评价**治理层自身的分层是否健康**。

## 冲突点

现有规则没有“分层健康度”判据，治理层因此可能在没有收敛信号的情况下，按目录对称或主题增补持续增生。这不是既有条文被违反，而是治理覆盖边界上的空白：等到未来需要按“最小必读集”收敛时，将面临大规模路径修改、导航重写与认知重建——属于 §1「高危维度 · 高迁移成本」，且 `organization-principles.md` 第 6 节本就为高迁移成本的结构决策开了频率无关的前置通道。

## 危害场景（§1 高危维度要求的具体场景陈述）

- 治理层无判据地增生 → 单任务最小必读集持续变大 → 协作者为保险全读，同时付深度和广度成本。
- 冗余（同一关切分散在能力层 / 流程规则 / intent）不被“单一归属”约束收敛 → 未来收敛时迁移成本随文档数量放大。

## 解决方案

- 在 `organization-principles.md` 新增 §10「分层是否健康，看单任务最小必读集」（路由精度 / 单一归属 / 可跳到叶子三个杠杆），并在 §11 清单补第 8 问。
- 该改动按 §1「高危维度 · 高迁移成本」触发；本记录即新锚要求的“写出具体场景 + 记入 `incidents/`”的落实，也是该锚机制的首次真实演练。

## 复发信号

- 完成一个典型任务需要读的文档数持续上升，且同一关切分散在多篇导致必须全读。
- 治理层新增文档主要靠目录对称或主题补齐，而非稳定能力位 / 职责位。

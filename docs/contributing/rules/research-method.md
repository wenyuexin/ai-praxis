# 研究方法与交付判断

本文件负责怎样开展、继续和收束有实质认识目标的研究。查找已有知识不自动触发本流程；只改错字、链接或格式时，做对应核查即可。设计理由按需读 [`intent/research-method.md`](../intent/research-method.md)。

## 1. 明确本轮目标与范围

- 开始或接续研究时，说清当前问题、主要范围与希望获得的认识；交付正文时，辨明目标读者及必要前置知识。可在任务说明或已有研究安排中简述，不新建固定目标表。
- 初期可先探索再收敛；目标发生实质变化时说明发现与调整理由，不在验收失败后仅缩小目标来宣布完成。
- 整体对象研究要辨认与目标有关的重要组成、关系与机制，区分本轮覆盖和后续内容。局部专题只补必要背景，不强制先做对象百科。
- 进入主线、出现重要发现及收束时，回看主线以外是否有影响目标的重要遗漏。研究单元与产物责任见 [`research-artifacts.md §2–§3`](./research-artifacts.md)。

## 2. 按缺口选择行动

优先处理会改变主要解释或判断的缺口。下表供选择，不是必走阶段：

| 当前缺口 | 可选行动 | 转换行动前应能判断 |
|---|---|---|
| 不知道材料是否存在、说了什么 | 读原文、附录、实现、配置或正式说明 | 已查到、未查到和材料未定义分别是什么 |
| 术语或关系混淆 | 定义辨析、相邻概念比较、正反例 | 区分条件与适用范围 |
| 知道部件却说不清怎样工作 | 推演数据和状态变化、检查公式、举例或改变条件 | 结果为何出现，哪些步骤仍不能确定 |
| 不清楚设计选择的意义 | 比较合理替代、反例与适用条件 | 条件怎样改变取舍，作者动机与研究者解释有何区别 |
| 结论依赖真实行为或效果 | 选择有判别力的观测或实验 | 是否已有行为证据；条件不足时具体还缺什么 |
| 材料足够但正文难理解 | 综合关系，补概念与过程解释，裁去重复流水 | 读者能否凭正文恢复主线 |

允许返回调查、分析或调整问题。原材料未定义的机制要说明其对结论的影响，不凭常识补成对象事实；教学例子和静态推演不冒充实际运行结果。

按研究对象选择核对动作：

- **开源实现**：固定观察版本，沿接口、配置和执行路径核对数据与状态，分清开源实现与服务端能力。
- **论文**：固定原文版本，连接问题、主张、方法与论证；按需要交叉核对公式、图、提示词、实验协议、对照和消融。
- **技术概念**：辨认定义、相邻概念、正反例、适用条件和解释用途。
- **理论、benchmark、比较研究**：按问题检查假设与推导、任务与指标的可观测性、共同条件下的比较尺度。

这些动作可组合，不是另一套研究单元分类。需要持续维护问题树时，按 [`research-artifacts.md §3.4–§3.6`](./research-artifacts.md) 的启用与提炼规则；理论或机制综述可选用 [`survey-template.md`](../../templates/survey-template.md) 的推导、预测与实验提示，不为填模板强套章节。

## 3. 将认识交付为解释

- 按读者要理解的问题组织正文，首次使用关键概念前给予足够说明，使主要关系和推理连续可读；例子、公式、图和比较按解释需要使用。
- 分清事实、推导、设计动机解释和建议，按其依据表达。影响行为与判断的限制贴着相关解释保留，不用重复免责声明挤占主线。
- 正文自身交付约定范围内的理解，不要求读者从长证据表、源码摘录或历史笔记拼接主要论证。具体产物分工仍由 [`research-artifacts.md`](./research-artifacts.md) 定义。
- 涉及输入回流、Evidence 与来源时，按 [`documentation-workflow.md`](./documentation-workflow.md) 和 [`evidence-and-traceability.md`](./evidence-and-traceability.md) 处理；本文件不另定义状态、字段或落位顺序。

## 4. 分别检查事实与理解

收束前对照目标检查两方面：

- **事实与论证**：关键判断是否被来源支持，版本与范围是否清楚，推断和外推是否适当。
- **覆盖与理解**：是否遗漏影响目标的重要内容，概念和过程能否连续理解，正文是否兑现预期所得。

理解检查可让读者解释关键关系、推演过程，或在条件改变后判断行为。完整对象、整篇论文或复杂机制交付，宜在写作早期明确代表性阅读任务，再对照正文检查；不设固定题量或得分。

重要或容易隐藏理解缺口的交付，优先由未参与写作的读者检查。说明其可用正文和前置知识；不能用来源补全正文后再宣称正文足够。事实检查可另读来源。AI 冷读仅作诊断，不证明真实人类学习效果。

不能以来源齐全、章节齐全、篇幅增长或所有问题已登记代替上述检查。发现缺口时，判断应补调查、分析还是表达，再回到相应行动。

## 5. 如实判断完成或暂停

停止时说明实际获得并交付了什么、哪些剩余缺口仍影响目标，以及本轮是目标达到、预算耗尽、条件受限还是等待材料；有明确价值时指出后续行动。说明可留在交付回复或已有研究安排，不强制正文增设固定尾章。

主线收口不推出对象完成；局部分析完成不推出整篇研究完成；事实得到支持不推出理解已经交付。把剩余问题登记或 park 也不能代替目标层的完成判断。

## 6. 按任务裁剪

小问题可在一次短回答中完成目标、来源核对、解释与结束判断。记录规模与任务相称，不强制问题树、独立协议、多 agent、实验、前后测、全量 API 扫描、完整过程日志或独立 source/evidence 文件。

验证方式由主张所需证据决定。没有旧正文就不制造改前对照；需要可复核对照时，保存实际可恢复的基线，不能仅留无法恢复首稿的 hash。目录与文件按组织需要创建，不按本流程成套补齐。

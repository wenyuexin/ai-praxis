# Overview 与结构研究辅助材料的设计意图

本文件不重复 [`../rules/metadata-files.md`](../rules/metadata-files.md) 和 [`../rules/research-artifacts.md`](../rules/research-artifacts.md) 的条文，而是解释：为什么 `overview.md` 必须保持独立的人类向成果，以及为什么原先由 `landscape.md` 承担的结构研究需求，在 B+C 模型下改由严格受限的研究辅助能力承接。

## 1. 这个文件回答什么问题

主规则负责回答：

- `overview.md` 解决什么问题、在什么情况下出现；
- 结构研究辅助材料何时可以出现、如何命名和回流；
- 为什么 `landscape.md` 不再是固定文件类型；
- 如果 B+C 实际失败，A 回退模型应如何重新评估。

本文件补充的是这些边界背后的设计理由，以及 AI 最容易产生的几种误读。

## 2. `overview.md` 的原意

`overview.md` 不是目录结构说明，也不是维护者的研究驾驶舱。它是一篇相对独立、面向人类读者的研究成果：

- 脱离同目录的 sibling 文档后仍应具备可读性；
- 读者不继续阅读其他文档，也应能建立相对完整的主题理解；
- 它的主要目标是表达经过整理的主题主线，而不是辅助构建其他文档；
- 它不应承接目录切分、维护路径、未闭合证据、临时计划或问题树。

当 `overview.md` 开始大量解释“本目录为什么这样切”或“各板块如何协作”时，先把稳定的目录定位和查找导航回流到 `README.md` / `index.md`。剩余内容如果仍是尚未稳定、需要独立维护的结构判断，再按 C 的准入条件评估；不要把 overview 改造成结构研究文。

## 3. 为什么退役 `landscape.md` 固定类型

原有 `landscape.md` 确实捕捉到一种真实需求：研究过程中有时需要独立保存多个文档或目录之间的边界、归属、协作和下钻路径判断。

但固定文件名带来的成本也是真实的：

- AI 容易把它理解成所有复杂目录都应创建的结构地图；
- 结构研究、主题综述、目录导航和对象长 notes 容易重新混在一起；
- `overview.md` 与 `landscape.md` 会被误读成一组对称、并列、长期维护的文件类型；
- “结构支架先于 overview”这一需求，容易被错误转化为“先建 landscape”。

B+C 保留真实需求，但不保留固定文件槽位：

- 稳定的目录定位和导航回到 `README.md` / `index.md`；
- 稳定的阅读、研究或建设顺序回到 `roadmap.md`；
- 缺口、候选对象和冲突回到各自元信息文件；
- 尚未稳定、确需独立维护且无法由上述 owner 承接的结构判断，才进入 C 的研究辅助材料；
- 结构判断稳定后必须回流，辅助材料不与 overview 长期并列成第二篇结构主文。

因此，退役固定类型不等于否认结构研究需求，而是把“真实需求”和“固定文件名”拆开。

## 4. C 不是第四层，也不是改名后的 landscape

C 是研究辅助层的一种条件性使用，不是新的固定元信息层：

- 它不要求每个领域或主题目录创建 `notes/`；
- 它不要求使用 `structure.md`、`research-structure.md` 或其他固定文件名；
- 它不允许创建 `notes/landscape.md` 作为隐含替代；
- 它不承接对象级源码笔记、长引用、证据表或普通研究过程；
- 它不承接 overview 的未完成草稿。

只有在多个并列文档或目录受到影响、材料需要独立反复维护、既有 owner 无法承接、且研究对象确实是文档体系结构判断时，C 才有合法入口。具体准入和 stop-line 由 [`research-artifacts.md §5.2`](../rules/research-artifacts.md) 承担。

## 5. “结构支架先于 overview”如何保留

这个需求仍然成立，但不再绑定某个固定文件名：

- 如果问题是目录定位，先形成 `README.md`；
- 如果问题是结构展示和查找入口，先形成 `index.md`；
- 如果问题是阅读、研究或建设顺序，先形成 `roadmap.md`；
- 如果问题是缺口、候选对象或冲突，先进入对应元信息文件；
- 如果上述文件都无法承接，而结构判断仍未稳定且需要独立维护，才启用 C；
- 当主线成熟时，再形成独立的 `overview.md`。

这保留了结构先于主文成熟的合法路径，同时避免把所有前置结构工作压成 `landscape.md`。

## 6. A 回退模型

如果实际维护证明 B+C 无法保持结构判断的可发现性，才重新评估 A。A 不是当前默认路径，也不能由单个目录自行启用。

A 启用后，`metadata-files.md` 是 `landscape.md` 的唯一规则 owner；它仍不代表主题地图、研究地图或稳定元信息层的通用成员。是否启用、如何定义触发阈值，需要另行形成治理决策。

## 7. 典型误读信号

以下说法通常说明边界已经漂移：

- “所有复杂目录都应该有一个 landscape。”
- “overview 负责主题，landscape 负责结构，所以二者总是并列。”
- “先建一个空的领域 notes，之后再往里填结构研究。”
- “把 `notes/landscape.md` 当作退役 landscape 的新名字。”

更稳的判断顺序是：先识别稳定 owner，再判断是否真的存在 C 的独立材料需求，最后才决定是否需要额外容器。

## 8. 本文件的使用方式

只有在以下场景才读：

- 需要修改 overview、结构研究辅助材料或 `metadata-files.md` 的相关条文；
- 需要解释为什么 `landscape.md` 固定类型被退役；
- 发现 AI 把 overview、导航、结构研究和对象 notes 再次压平成对称文件类型；
- 需要评估 B+C 是否失败，以及是否满足 A 的回退前提。

平时执行文档治理或研究组织任务，仍优先读对应规则文件。
